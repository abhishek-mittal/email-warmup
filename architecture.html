EmailWarm — Built vs. Pending

  • 18 modules · 60+ REST endpoints

Backend modules

Click a module to see what's inside
AuthModule
Built
better-auth bearer-token guard · user sync on first sign-in · internal endpoint shared-secret auth.
5 controllers · 5 services
Highlights:
  • BetterAuthGuard — HMAC verify, redact header in logs
  • UserSyncService.upsertUser — wires plan='trial', 7-day default
  • internal.controller.ts — POST /internal/user-sync
InboxModule
Built
Connect Gmail/Outlook/SMTP/IMAP, store encrypted creds, run pre-check, bulk batch upload.
inbox + imap + smtp + oauth + dto
Endpoints:
  • POST /inboxes/connect/{gmail,outlook,smtp}
  • POST /inboxes/batch, /batch/csv
  • Per-step precheck errors (422 with errCode, host, port)
WarmupModule
Built
The brain. Daily ramp, pairing, send + receive + engage. The whole reason EmailWarm exists.
10 processors + 5 services
Services: WarmupService (schedule + pause/resume), RampService (linear, cap 200), PairingService (same-domain hard block), ContentService (Claude + 50-template fallback)
Processors: WarmupSendProcessor · WarmupReceiveProcessor (rescue→open→star→reply→file)
MonitorModule
Built
DNS + RBL checks. SPF/DKIM/DMARC/MX/rDNS via Cloudflare/Google DNS. 8-zone blacklist with 5s timeouts.
2 processors · 2 services · 8 RBLs (out of 100+ planned)
Crons: 0 6 * * * daily DNS · 0 0,6,12,18 * * * every 6h blacklist
Real bug caught: rDNS skip when sendingIp unset; first-ever check never alerts.
ScoringModule
Built
Composite 0–100 reputation score from DNS + blacklist + placement, with trend and 90-day history.
3 services · 1 processor · 1 controller
Algorithm: DNS (40) + Blacklist (20) + Placement (40) — each component has its own scoring function.
Real bug caught: trend requires ≥4 rows before up/down, else 'stable'; never alerts newly-connected inbox.
PlacementModule
Built
Send to seed list (10 quick / 35 full) via BCC with shared Message-ID. Classify Gmail X-GM-LABELS + Outlook/Yahoo folders.
4 services · 1 processor · 1 controller
Plan quotas: trial/starter:1 · growth:5 · agency:unlimited (429 via HttpException)
Real bug caught: X-GM-LABELS \Category_Social→missing (not primary), kept Promotions distinct from Spam.
DiagnosticsModule
Built
AI-powered cause analysis (Claude) with issue codes & fix steps · readiness report at graduation.
3 services · 2 processors · 1 controller
Triggers: manual · auto_blacklist · auto_drop
Queue: diagnostics · readiness-report
NotifyModule
Built
Email alerts via Nodemailer + Slack webhook delivery for every event type.
2 services · 1 processor
Events: blacklist_hit · score_drop · warmup_graduated · trial_expiring · dns_critical · diagnostics_ready
BillingModule
Built
Stripe checkout + webhook + portal · trial service · plan-gating helpers (assertInboxLimit, assertPlan).
3 services · 2 controllers
Tiers: trial · starter · growth · agency · enterprise
Stripe webhook writes to stripe_events for idempotency
AnalysisModule
Span
Initial inbox & pool-inbox analysis — DNS + health score on every uploaded row.
1 service · 1 processor
Queue: inbox-analysis
Anti-cycle pattern: exposes read methods as plain functions to avoid Nest DI import cycle (Inbox → Analysis → Monitor → Warmup → Inbox)
PoolInboxModule
Built
Private pool CRUD + reanalyze route. The other half of the closed-loop warmup.
3 controllers/services
Endpoints: GET/POST/DELETE /pool-inboxes[/:id] · POST /pool-inboxes/:id/analyze (resets pending, enqueues analysis)
ActivityModule
Built
9 endpoints powering the 5-tab inbox activity dashboard. NDJSON log tail for the Logs tab.
9 endpoints · T027
Endpoints: activity, sends, dns-history, blacklist-history, placement-history, score-history, logs, POST checks/dns, POST checks/blacklist
PoolInboxActivityModule
Built
Pool inbox panel endpoints — 4-tab slide-over + connection-summary strip (no secrets shipped).
5 endpoints · T028
Endpoints: connection-summary · activity · activity-stats · pairings · logs
InboxControlModule
Built
Single + bulk pause/resume with ownership-checked 404. Resume re-queues today's sends immediately.
4 endpoints · bulk body ≤ 200 ids
Endpoints: POST /inboxes/:id/pause · resume · POST /inboxes/pause (bulk) · resume (bulk)
QueueModule
Built
11 BullMQ queues registered · QueueService wraps add/getJobCounts/removeJobsForSender/Receiver.
11 queues · queue.module.ts
Retention: completed kept 1k×24h · failed kept 500×72h
MonitorModule

Only 8 RBLs implemented (Spamhaus + 7 zones). Spec asks for 100+ — backlog is real.
8 / 100+ RBLs
Gap: monitor/rbl-list.ts ships with 8 minimum zones. The 100+ target needs MXToolbox/Spamhaus commercial feeds.
OD005: decision pending — buy RBL feed vs build vs ship with 8.
NotifyModule
Partial
Email + Slack channels wired. SMS + in-app toast channel not implemented.
2 / 4 channels

Pending: in-app toast (queued behind frontend plan) · SMS (no provider picked)
T029 · Real-seen detection
Designed
Wave 13. Detect real human opens via on-demand IMAP \Seen refresh, not just our worker-set flags.
spec written · migration 0005 designed
Path A: opportunistic snapshot in WarmupReceiveProcessor (before simulated open) — if \Seen already true → real human open
Path B: POST /inboxes/:id/refresh-real-opens (synchronous, ≤50 rows/30d window, idempotent)
Schema: opened_source ('simulated' | 'imap_rescan')
