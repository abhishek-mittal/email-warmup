PART 0

What this tool does, in plain words

A brand-new email address is a stranger to the big mail companies (Gmail, Outlook, Yahoo). If it suddenly sends a lot of mail, they get suspicious and put the mail in spam.

EmailWarm builds trust slowly. Your new address sends a few harmless emails a day to friendly helper addresses. The helpers open them, reply, and rescue them if they land in spam. Every day it sends a few more. After a few weeks the mail companies treat your address as normal and trustworthy.

Mailbox to warmsends →Helper mailboxopens, replies, files in WarmupHub →Mailbox to warmscore goes up

The four kinds of mailbox

Mailbox to warm

The address you want to build a reputation for. EmailWarm calls it an inbox. You connect it on the Accounts page.

Helper mailbox

A friend address that trades emails with the one being warmed. EmailWarm calls it a pool inbox. It is never warmed itself. You add it on the Warming Pool page.

Judge mailbox

Used only in a placement test. A test email goes to several judges, and they report whether it landed in the inbox or in spam. EmailWarm calls them seeds.

Other customers

The shared pool. On your own computer there are no other customers, so your helpers do all the work.

Read before you connect anything

Warming sends real emails from the address you connect, and nobody can recall them. Start with an address you can afford to lose, not your main business mailbox. Helper addresses must be on a different domain from the mailbox being warmed (for example, warm you@yourcompany.com and use helpers at @gmail.com and @outlook.com). The tool refuses to pair two mailboxes on the same domain.

PART 1

Gather what you need

About 20 minutes. Tick each item when you have it.

One mailbox to warm

A real address you can log in to. Ideally a new or low-stakes one. Write down its domain (the part after the @).

Two or three helper mailboxes

Real addresses on different domains from the mailbox to warm. A mix works best: one Gmail, one Outlook or Yahoo, one more if you have it. You will need to log in to each one to read what arrives.

Three more mailboxes as judges only for Part 8

Placement tests need at least 3 judge mailboxes. Gmail, Outlook and Yahoo addresses work. Keep them separate from your helpers if you can. You can skip them for now and add them when you reach Part 8.

A computer with Docker, Node and pnpm

This is the project you already run. If docker --version and pnpm --version both print a number in a terminal, you are ready.

Two-step login switched on for every mailbox needed for app passwords

Gmail and Yahoo only give out app passwords (Part 3) when two-step verification is on. Turn it on in each account's security settings now.

PART 2

Start the app

You need three things running: the database, the backend (the engine) and the frontend (the website).

Start the database and Redis

Open a terminal and run:

Terminal 1, in the email-warmup folder
docker compose up -d
You should see

Two lines ending in "Running" or "Started". Done.

Start the backend

Terminal 2
cd backend
pnpm install
pnpm db:migrate
pnpm start:dev
You should see

After about a minute, a line saying the app is listening on port 4611. Leave this terminal open. It is where the warm-up emails are logged.

To double-check, open a third terminal and run:

curl localhost:4611/health
You should see

A short reply that contains "ok".

Start the website

Terminal 3
cd frontend
pnpm install
pnpm dev
You should see

"Ready" and a local address. Open localhost:3000/sign-in in your browser.

Remove the demo data

Your database may hold pretend mailboxes made for screen testing. They would become your warm-up partners, and emails sent to them bounce, which makes the tool pause your real mailbox. Remove them first:

Terminal 3 or any terminal, in the backend folder
cd backend
pnpm db:seed:dev --reset
You should see

"Demo data removed." Your real mailboxes are never touched by this command. It only removes pretend addresses ending in .test.

Later

When you want the pretend data back for screen design, run pnpm db:seed:dev again. Remove it again before the next real test.

Sign in

Use the test account that has every feature switched on:

Emailadmin@emailwarm.dev
PasswordEmailWarm-Phase1-Test!
You should see

The Overview page with an empty list of mailboxes.

PART 3

Get app passwords

An app password is a special password that lets one program use your mailbox without your real password. Use one for every mailbox you add. Your normal password will not work. You do this once per mailbox, in the mail company's own website.

Gmail

  1. Go to myaccount.google.com/apppasswords and sign in.
  2. Type a name such as "EmailWarm" and press Create.
  3. Copy the 16-letter code Google shows. You will not see it again. Spaces do not matter.
If the page says it is not available

Two-step verification is off for that account, or a company admin has turned app passwords off (common on Google Workspace). Turn on two-step verification first, or use a personal Gmail instead.

Yahoo

  1. Open Yahoo Account Security and go to Generate app password.
  2. Pick "Other app", name it "EmailWarm", and copy the code.

Outlook or Microsoft 365 can be fussy

In your Microsoft account's security settings, under two-step verification, look for App passwords and create one. Many Microsoft work and school accounts have this turned off, and then no password will work for SMTP. If Outlook refuses, use Gmail, Yahoo or Zoho for this test instead, and add Outlook later once you have set up the Google and Microsoft sign-in (see "Advanced" at the end of Part 5).

Your own domain (for example you@yourcompany.com)

Ask whoever hosts your mail (Zoho, GoDaddy, Namecheap, cPanel, and so on) for four things: the SMTP server and port, the IMAP server and port, and the username (usually the full email address) and password. Port 587 is the usual SMTP port and 993 the usual IMAP port.

PART 4

Add your helper mailboxes

Do this before connecting the mailbox to warm, so it has partners from its very first send.

Open the Warming Pool page

In the left menu click Warming pool. It says "No pool inboxes yet." At the top right are two buttons: Add via wizard and Add via CSV.

Add the first helper with the wizard

  1. Click Add via wizard.
  2. Set the provider to Custom, even for a Gmail or Outlook address. Do not pick Gmail or Outlook here: those ask for a Client ID, Client secret and Refresh token that you do not have. Then press a provider quick-fill button to type in the servers and ports for you.
  3. Fill in: Email address, SMTP host / port / user / password, and IMAP host / port / user / password. The user is the full email address. The password is the app password from Part 3, in both places.
  4. Press add. Use Add another to add the next helper in the same sitting.
You should see

The helper appears in a grid. Its status starts as pending and turns active within a minute, after the tool checks its settings.

If it says "Couldn't add this entry"

Read the reason under it. The usual cause is a typo in the app password or a wrong port. A "duplicate email" message means that address is already in the pool.

Add two or three helpers in total

More helpers means more variety, and each helper only handles a limited number of partners a day. Make sure at least one helper uses a different provider from the others.

You should see

All helpers showing active and a health score. Click one to open its page. It has tabs for Activity, Pairings and Logs, which stay empty until emails flow.

Prefer a spreadsheet?

"Add via CSV" takes a file with a header row and these columns in any order: email, provider, and the SMTP and IMAP fields. Use it when you have many helpers. For two or three, the wizard is easier.

PART 5

Connect the mailbox to warm

Open the connect page

Click Accounts in the left menu, then the connect button, or go straight to localhost:3000/inboxes/connect. You will see three cards: Connect with Google, Connect with Microsoft, and Custom SMTP / IMAP.

Use the third card

The Google and Microsoft buttons need sign-in keys that are not set up on your computer yet (they are placeholders). The Custom card works with any mailbox, including Gmail and Outlook, using the app password.

Fill in the Custom SMTP / IMAP form

  1. Press the quick-fill button for your provider (Gmail, Outlook, Yahoo or Zoho). The servers and ports fill in.
  2. Type the Email address, SMTP user (the full address) and SMTP password (the app password).
  3. Make sure the IMAP box is ticked (the quick-fill button ticks it for you) and fill the IMAP user and password the same way. This matters: without IMAP the tool can send but cannot receive, open, reply or file mail, so the mailbox cannot join the pool.
  4. Leave DKIM selector empty for now.
  5. The box Join the shared warmup pool is for swapping mail with other customers. With no other customers on your computer, leave it off for this first run. You will try it in Part 10.

Press Connect and wait for the test

The tool now tries to log in to the sending server, then to the receiving server, then creates a folder called WarmupHub in your mailbox. This takes 5 to 30 seconds.

You should see

A green result showing the SMTP and IMAP checks with the time each took, then the mailbox on the Accounts page with status active. Open the real mailbox in another tab: a new folder (a label in Gmail) called WarmupHub is there. That proves the tool can log in and file mail.

If the test fails

The message tells you which step failed. "Wrong username or password" means the app password. A timeout usually means a wrong port or a network that blocks mail ports. Nothing is saved when the test fails, so just fix the field and try again. More fixes are in Part 12.

Advanced, optional: make the Google and Microsoft buttons work

Only needed if you want one-click sign-in for mailboxes. In the Google Cloud or Azure console, create an OAuth app and add this redirect address: http://localhost:3000/api/mailbox-oauth/callback/gmail (use /outlook for Microsoft). Put the client ID and secret into backend/.env (GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, MICROSOFT_CLIENT_ID, MICROSOFT_CLIENT_SECRET) and into frontend/.env.local, then restart both. Google may mark an unreviewed app as "testing"; add your own address as a test user.

PART 6

Check its health

Before sending, make sure the sending address is set up properly in DNS. These records are what prove an email really comes from you.

Open the mailbox page

On Accounts, click your mailbox. At the top you see its status, score and trend. Below are five tabs: Activity Feed, DNS & Blacklist, Sent Emails, Placement, and Logs.

Run the DNS check

Open the DNS & Blacklist tab and press Run DNS Check Now. It shows five rows:

RowWhat it means in plain words
SPFA list saying which servers may send mail for your domain.
DKIMA secret signature that proves the email was not changed on the way.
DMARCYour instructions to receivers about what to do with mail that fails the other two.
MXWhere mail for your domain is delivered.
rDNSYour sending address looks up back to your domain. Rarely blocks mail but helps.
You should see

Green ticks for SPF, DKIM and MX at least. Gmail, Outlook and Yahoo addresses are set up by the provider, so they usually pass. A row marked "unknown" means the tool could not check, which is different from failing.

If a row is red on your own domain

Open the diagnostics page for the fix steps in plain words, then add the record where you manage your domain's DNS (your domain registrar or host) and press the check button again. DNS changes can take up to an hour.

Run the blocklist check

On the same tab press Run Blacklist Check Now. This asks several public "bad sender" lists whether your address or domain is on them.

You should see

"Clean". If one list is listed, warm-up pauses on its own and you will see why on the mailbox page.

PART 7

Make it send, and watch

The most common surprise: nothing sends right away

EmailWarm plans each day's emails once, at 05:00 UTC (10:30 in the morning in India). It then spreads them across the window from 08:00 to 18:00 UTC (1:30 pm to 11:30 pm India time), with random delays and at least 8 minutes between emails. The first day sends only 3 emails on the Medium speed (2 on Slow, 5 on Fast).

If you connect during the window, you can start now with the Pause then Resume trick in the next step. If you connect after 18:00 UTC, no slot is left today and the first emails go out tomorrow. That is normal.

Start today's sends now

  1. On the mailbox page, press Pause. The status becomes paused.
  2. Press Resume. Its hint says "schedule today's sends immediately".
You should see

Status back to active. In the backend terminal (Terminal 2) lines appear about scheduling the day. On the Activity Feed tab, upcoming sends appear and then turn into "sent" events over the next minutes and hours.

If nothing is scheduled

Check three things: the mailbox is active; you have at least one active helper on a different domain (Part 4); and the current time is before 18:00 UTC. With no partner the tool sends nothing, by design.

Follow one email through its life

Keep the mailbox page open on Activity Feed, and log in to one helper mailbox in another tab. Over a few minutes to a few hours you will see these events:

EventWhat happenedWhere to see it
SentThe tool delivered an email to a helper.Activity Feed; Sent Emails tab; the helper's inbox or spam folder
FiledThe helper moved it into its WarmupHub folder so it never clutters a real inbox.The helper's WarmupHub folder
RescuedThe email landed in spam and the helper moved it out. A good sign that the tool is working.Activity Feed
Opened / StarredThe helper read it, sometimes starring it.Activity Feed
RepliedThe helper wrote back. The reply arrives in your warmed mailbox's WarmupHub folder.Activity Feed; your mailbox's WarmupHub folder
Spam landedThe email went to spam before rescue.Activity Feed (red)
You should see

Within a day: several "sent", most "filed", some "opened", a few "replied". Also open the Logs tab for the technical story, and the helper's own page on the Warming Pool page (Activity, Pairings and Logs tabs) for the other side.

Patience

Opens and replies are deliberately delayed to look human, so they can arrive minutes or hours after the send. Check back later instead of pressing buttons.

Look at the live pool status

Open the Warming pool page and click a helper. The live status panel updates by itself every few seconds and shows what the helper is doing right now. If it ever shows a short error, it keeps trying and recovers.

PART 8

Run a placement test

This answers the question that matters most: where does my mail actually land? It needs at least 3 working judge mailboxes.

Add your judge mailboxes

Judges are added by an operator command, not on a web page. First find your internal secret: open backend/.env and copy the value after INTERNAL_SECRET=. Treat it like a password and do not paste it anywhere public. Then run this once per judge, filling in the capitals:

Any terminal
curl -X POST localhost:4611/internal/seeds \
  -H "x-internal-secret: YOUR_INTERNAL_SECRET" \
  -H "content-type: application/json" \
  -d '{"email":"JUDGE@gmail.com","provider":"gmail","imapHost":"imap.gmail.com","imapPort":993,"imapPass":"APP_PASSWORD"}'

For Outlook use "provider":"outlook" and outlook.office365.com. For Yahoo use "provider":"yahoo" and imap.mail.yahoo.com.

Then ask the tool to check that every judge can log in:

curl -X POST localhost:4611/internal/seeds/check \
  -H "x-internal-secret: YOUR_INTERNAL_SECRET"
You should see

Each judge reported as healthy. A judge that cannot log in is set aside automatically and not counted.

Run the test

  1. Open your mailbox page and the Placement tab.
  2. Press Run Placement Test.
You should see

A test that starts as queued, then running, and finishes in a few minutes. The result shows the share of judges where the email landed in Primary, Promotions and Spam, and how many were missing. For a new address a high spam share is normal. It should shrink as warming goes on.

How many tests can I run?

The admin test account has unlimited tests. Other plans have a monthly limit: trial and Starter one, Growth five. If a test cannot start because too few judges are healthy, you are told straight away and no test is counted.

If it says "too few seed mailboxes"

You have fewer than 3 healthy judges. Add more or fix the one that failed its check, then run the test again.

PART 9

Score, graduation, diagnostics

Read the score

The score (0 to 100) is recalculated daily from three things: your DNS health, your blocklist status and your placement results. The arrow beside it shows whether it is going up, down or staying level. A score only counts on days when real measurements were available, so do not worry if the first couple of days look low.

Understand graduation

A mailbox graduates when all of these are true: it has been warming long enough (Fast 21 days, Medium 35 days, Slow 56 days); it has 7 days of measured scores averaging 80 or more; and a placement test from the last 14 days shows spam at 5% or less. If everything else is ready and there is no recent test, the tool starts one free test by itself.

On graduation the mailbox's status becomes graduated, it leaves the pool, you get an email and a readiness report with the recommended daily sending volume. You cannot skip the waiting days. That is the whole point.

Ask for an AI explanation needs a key

Open the diagnostics page for the mailbox (the diagnostics link on its page) and press the request button. The tool collects the evidence and asks Claude to explain the likely causes and the fixes in order.

This needs a real ANTHROPIC_API_KEY in backend/.env (it is a placeholder now) and the Growth plan or above. The admin test account qualifies. Without a key you still get the plain list of detected problems with fix steps, just not the AI summary.

PART 10

Pause, resume, disconnect, join the shared pool

Try Pause and Resume

On the mailbox page, Pause stops all new sends and clears the waiting ones. Resume starts again. Pausing is always safe, and warm-up progress is kept.

Some pauses are done by the tool itself, and the page tells you why:

Reason shownWhat it meansWhat to do
Bounce rateToo many emails to this mailbox's partners were rejected.Check the helper addresses are real, then resume once the hold is lifted.
BlocklistThe address appeared on a "bad sender" list.Follow the diagnostics steps to get delisted. It resumes after a clean check.
Access revoked or expiredThe app password was cancelled or changed.Make a new app password and use the reconnect button.
Plan changeThe plan no longer includes warm-up.Change plan on the Plan & credits page.

Try joining and leaving the shared pool

On the mailbox page find Pool participation. Joining means this mailbox trades emails with other customers' mailboxes too. Leaving takes it out of pairing straight away, but emails already delivered cannot be taken back. On your own computer there are no other customers, so you will only see the status change and the pool membership record, not extra traffic.

Check the other pages

  • Plan & credits: your plan and the demo credits. Billing is in test mode, so no real money moves.
  • Account: download all your data, or delete your account. Deleting disconnects every mailbox and erases the saved passwords. Only do this when you are finished testing.

Know which screens are previews

Some pages show sample data and a dashed "Preview" banner: Analytics, Deliverability, Placement tests, Sending domains, Templates, API keys, Audit log, Onboarding, and most Settings pages. They are design drafts and are not connected yet, so do not judge the real product by them. Everything on the Accounts, Warming pool, Plan & credits and Account pages, and everything on a mailbox's own page, is real. The page called Feature review lists them all.

When all else fails

The backend terminal (Terminal 2) prints what the engine is doing. Copy the last 20 lines when you ask for help. Never paste app passwords or your internal secret.

PART 13

Words you will meet

Warm-upSlowly raising how much a new address sends, with friendly engagement, so mail companies learn to trust it.
RampThe daily plan for how many emails to send. It grows day by day. Slow, Medium and Fast are different growth speeds.
JitterA random delay added to each send so the traffic does not look robotic.
Inbox, pool inbox, seedMailbox to warm, helper mailbox, judge mailbox (Part 0).
WarmupHubThe folder or label the tool makes so warm-up mail never mixes with your real mail.
RescueMoving an email from spam back to the inbox. It teaches the mail company that the sender is wanted.
SPF, DKIM, DMARCThree DNS records that prove an email is really yours (Part 6).
BlocklistA public list of bad senders. Being on one gets mail blocked.
BounceAn email that could not be delivered. A hard bounce means the address does not exist.
PlacementWhere an email lands: Primary, Promotions, Spam, or missing.
GraduationThe point at which a mailbox is warm enough to send real campaigns (Part 9).
App passwordA special single-use password for a program (Part 3).
