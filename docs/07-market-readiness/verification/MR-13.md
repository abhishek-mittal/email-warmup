## Before

- Every blocklist zone was queried as `<domain>.<zone>`, including IP lists. Any `127.*` answer counted as listed, so a Spamhaus "query refused" answer (`127.255.255.254`) paused a healthy inbox.
- A check where nothing answered was stored as clean.
- Three of the eight zones no longer exist (two SORBS zones, `combined.abuse.ch`).
- DNS outcomes were pass or fail only; a timeout was reported as a missing record. The connect pre-check hardcoded DKIM as passing. A DMARC record with no version or policy passed. DMARC `p=none` was a failure.

## What changed

**Blocklists.** `rbl-list.ts` is a registry: per zone, whether it lists IPs or domains, which answers are listings and which are operator errors. IP zones are asked about `inboxes.sending_ip` with octets reversed, and report `unknown` when it is not set; a domain's A or MX address is never substituted. Refusals, timeouts, undocumented answers and disabled zones are `unknown`. `is_clean` is true, false, or null when nothing answered. Only a real listing pauses an inbox. `SPAMHAUS_DQS_KEY` switches Spamhaus queries to keyed hostnames.

**DNS.** Outcomes are pass, fail or unknown; unknown is stored as null. SPF: exactly one record, at most ten lookup terms. DMARC: `v=DMARC1`, exactly one record, a valid policy; `p=none` passes with an advisory code. MX: null MX fails. DKIM: checked at the owner's selector if set; otherwise the provider's usual selectors are tried and a miss is unknown, never pass or fail. The connect pre-check and import analysis use the same service.

**Activation.** The connect pre-check now blocks only on a definite SPF or MX failure. Unknown results, an unverifiable DKIM selector and missing DMARC are recorded as issues but do not stop the inbox.

Dashboard: blocklist panel shows how many lists answered; four new issue explanations (`SPF_INVALID`, `DKIM_INVALID`, `DMARC_INVALID`, `DMARC_NONE`).

## Not done

- **Coverage is 5 live zones, not the "100+" in the PRD.** Decision needed: licensed aggregator access, or change the claim.
- Without a Spamhaus key, both Spamhaus zones will normally report unknown from cloud hosts. Not verified against the live service.
- Gmail and Outlook inboxes have no stable sending IP, so IP lists stay unknown for them. Custom inboxes need `sending_ip` set; there is no UI field for it.
- SPF is not evaluated against the actual sending IP; DKIM key strength and DMARC alignment are not checked.
- IPv6 sending addresses are not supported for IP lists.
- No comparison against independently captured live DNS records.
