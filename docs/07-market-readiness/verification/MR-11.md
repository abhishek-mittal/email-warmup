# MR-11: untrusted inputs, egress and secret handling

**Owner:** Claude · **Date:** 2026-10-03 · **Base commit:** `0ad4c44` · **Branch:** `feat/mr-warmup-core` (uncommitted) · **Status:** in progress

Same environment and command results as [MR-12](MR-12.md). Tests: `backend/src/common/egress-policy.spec.ts` (45), 6 cases in `backend/test/integration/safety.int-spec.ts`, Slack URL and import-limit cases in `backend/src/safety/safety.controller.spec.ts`.

## Done

- **Mail host egress policy.** Customer-supplied SMTP and IMAP hosts (inboxes and pool inboxes) are resolved, every answer must be a public address, and the connection is made to the checked address with the name kept for TLS only. Refused: loopback, private, carrier-grade NAT, link-local including `169.254.169.254`, multicast, reserved, IPv6 equivalents, IPv4-mapped IPv6 in dotted and hex form, NAT64 and 6to4 prefixes. A name with mixed public and private answers is refused. `MAIL_EGRESS_ALLOWLIST` lets an operator permit specific hosts or addresses.
- **Slack destinations** must be `https://hooks.slack.com/services/…`; redirects refused; 10-second timeout.
- **Imports** capped at 1 MiB and 200 mailboxes, enforced server-side for CSV and JSON.
- **CORS** restricted to `CORS_ORIGINS` or `APP_URL`.
- **Connect responses** no longer return credential ciphertext (done under MR-08/MR-10).
- **Failed custom connects** no longer leave a pending inbox row holding credentials.

## Done (2026-10-04 update)

- **Rate limits.** `@nestjs/throttler` global guard keyed per user (falls back to
  client IP) — `UserThrottlerGuard`. Default 300 req/min; a 20 req/min bucket on
  inbox connect (`/inboxes/connect/smtp`), batch import (JSON + CSV, both the
  inbox and pool-inbox controllers), placement runs (`/inboxes/:id/placement-test`)
  and the OAuth callback. `/health` is exempt. Tests: `throttler-user.guard.spec.ts` (3).
- **Global ValidationPipe.** `whitelist + forbidNonWhitelisted + transform` applied
  in `main.ts`. The two batch routes are deliberately typed loosely so one bad
  row still lands in `failed[]` (T020 partial-success) instead of a 400; per-row
  validation stays in the service layer.
- **Security headers.** `helmet` (nosniff, frameguard, HSTS, referrer policy; CSP
  and cross-origin resource policies disabled as this is a JSON API behind the
  frontend proxy).
- **Log redaction extended.** Added cookies, `set-cookie`, `x-internal-secret`,
  `smtpPass`/`imapPass`, `clientSecret`, `refreshToken`, `accessToken`, OAuth
  `code`/`state` (body + query) and the nested `inboxes[*]` import credentials.
- **Encryption key validated at boot.** `ENCRYPTION_KEY` must match `^[0-9a-fA-F]{64}$`
  (32 bytes) or the process fails startup. Tests: `env.validation.spec.ts` (4).

Verified: backend `npx tsc --noEmit` clean, 608 unit + 121 integration tests pass,
`nest build` clean.

## Not done

- Redis-backed throttler storage (in-memory counts per process; multi-instance
  Cloud Run multiplies the effective limit — follow-up with MR-19).
- Full DTO sweep is partial: the global pipe now validates every class-typed body,
  but batch rows still pass through the hand-written per-row validator by design.
- Allowlisted response DTOs on every `.returning()` path.
- Protocol debug logging is still controlled only by `LOG_LEVEL` (no prod force-off).
- Key rotation / versioned ciphertext.
- Rebinding was tested with injected resolver answers, not a live controlled resolver.
- OAuth providers use fixed hosts and are not passed through the policy.
