## Decision recorded (2026-10-03, owner)

Account deletion **anonymizes** the send ledger instead of erasing it. Each send row is also part of the partner's history; deleting it would corrupt another customer's statistics, bounce rate and pairing limits.

## Done

**Disconnect inbox** (`POST /inboxes/:id/disconnect`, button on the inbox page). Releases reserved sends, drains queued jobs, closes the IMAP connection, deactivates pool membership, erases all stored credentials, sets status `disconnected`. History stays; the inbox no longer uses a plan slot. Relinking the same Gmail or Outlook mailbox revives it.

**Export** (`GET /account/export`, Account page). Account, inboxes, pool inboxes, up to 5,000 most recent sends. No credentials.

**Delete account** (`POST /account/delete`, Account page). Requires the account email typed as confirmation. Then:

| Data | What happens |
|---|---|
| Stored credentials, tokens, pool credentials | erased |
| Inbox and pool addresses, user email | replaced with `deleted-<random>@deleted.invalid` |
| Mail hosts, usernames, DKIM selector, sending IP | erased |
| DNS check records, diagnostics, inbox analysis, notifications, pending link tickets | deleted |
| Send rows | kept; subject, bounce detail, failure text and server response erased |
| Reserved sends to the account's pool inboxes | canceled |
| Blocklist, placement and score rows | kept (numbers only, tied to an anonymized inbox) |
| Sign-in user, sessions, linked accounts | deleted; signed out everywhere |
| Stripe customer and subscription ids | erased locally |

**Password reset.** Link by email, valid once for 30 minutes; a new password revokes all sessions; the response is the same whether or not the address has an account; 3 requests per 15 minutes. The web app asks the API to send the mail (`POST /internal/auth-email`, internal secret, link must be on this site).

Live on the dev stack: reset request for an unknown address returns the generic 200; mail endpoint 401 without secret and 400 for a link on another site; account routes 401 signed out.

## Not done

- **Reset email delivery was not observed.** The dev platform SMTP settings are placeholders; the reset-and-sign-in round trip has not been run.
- Deletion does not require recent re-authentication, only a signed-in session plus the typed email.
- **Stripe is not told.** An active subscription must be canceled separately; deletion only erases the ids here.
- No email verification at signup.
- Job payloads already in Redis, application logs and database backups are not purged; no retention sweep exists.
- Custom SMTP inboxes cannot be reconnected in place; connecting again creates a new inbox.
- User sync at signup is still fire-and-forget.
- Privacy policy, terms and support pages do not exist. The wording on the Account page needs legal review.
