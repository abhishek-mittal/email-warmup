## Original defects

- `token-refresh` jobs were queued with no consumer. The audit counted 10 processors for 11 queues; the missing one was this.
- SMTP and IMAP used the stored access token with no refresh, so OAuth inboxes stopped working about an hour after connecting.
- Interactive Gmail stored no IMAP host; the pre-check then failed for every Gmail connect.
- Outlook used port 587 with implicit TLS; pool Outlook used port 465, which Microsoft 365 does not offer.
- Batch-imported OAuth inboxes had a refresh token but no access token, and were activated by DNS analysis alone.

## What changed

- `provider-config.ts`: one table of endpoints and TLS modes. Gmail SMTP 465 implicit TLS; Microsoft SMTP 587 STARTTLS; IMAP 993. Custom servers on other ports must upgrade with STARTTLS unless `MAIL_ALLOW_INSECURE_TRANSPORT=true` (test harness only).
- `MailCredentialService`: refreshes shortly before expiry, one refresh per credential (in-process single flight plus a Postgres advisory lock), stores the new expiry and any rotated refresh token encrypted. `invalid_grant` sets the inbox to `error` / `credentials_revoked` and deactivates its pool membership once. Other failures leave credentials untouched.
- `TokenRefreshProcessor` consumes the queue and re-arms itself.
- Imported and pool inboxes are activated only after SMTP (and IMAP where required) actually authenticate; the update is conditional on `pending`.
- Connection, greeting and socket timeouts on SMTP and IMAP; pooled IMAP connections are closed on shutdown.

## Not done

- Real Gmail and Outlook accounts across an access-token expiry and a worker restart (the task's done-evidence).
- No notification is sent on revocation; the notify processor has no template for it (MR-18). The inbox page shows the reason and a reconnect link.
- A pooled IMAP connection is not proactively reconnected after a credential change; it reconnects when the server drops it.
- **Behaviour change to confirm:** custom SMTP on ports other than 465 now requires STARTTLS. A server offering only plaintext will be refused.
