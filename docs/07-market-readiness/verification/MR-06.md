## Defects found and fixed

- Backend image ran `npm ci` with no npm lockfile. Now pnpm, pinned to 11.8.0 (the version the lockfiles need; pnpm 9 rejects the workspace file). CI is pinned to the same.
- **The image entrypoint was wrong.** The build emits `dist/src/main.js`, not `dist/main.js`; the old `CMD` and `start:prod` could never have started.
- The frontend could not build without a database: the auth route created its database pool at import. It is now created on first request.
- CI and deploy used `projects/email-warmup/...`; the repository root is this project.
- Deploy referenced Clerk secrets, an auth step with no id, and no Better Auth or internal secrets.

## Added

- `GET /health/ready`: 503 unless database and queue answer within 3 seconds.
- An uncaught exception now marks the process unready and exits after draining, instead of logging and continuing. Unhandled promise rejections are still logged and survived.
- Default job retry: 3 attempts with backoff for jobs that set none.
- `src/db/migrate.ts`: migration entrypoint for a release job; honours `MIGRATION_DATABASE_URL`.
- `.dockerignore` for both images.
- `deploy.yml` rewritten: runs only after CI passes on main, migrates before rollout, API with always-on CPU, web as the public entry.

## Not verified, not done

- **`deploy.yml` has never run.** Workload identity, service account, Secret Manager names (`emailwarm-*`), the `emailwarm-migrate` job and repository variables (`APP_URL`, `API_URL`, SMTP settings) are assumptions.
- **Web to API access is unresolved.** The API is deployed private, but the web proxy does not attach a Cloud Run identity token. Either add that, or put the API on internal ingress with a VPC connector. Until then the web app cannot reach a private API.
- Better Auth tables are still created by the web app at first request, not by a migration job.
- CI has not run on GitHub.
- API and workers still share one process; no worker heartbeat in readiness.
- No rollback step, no restore rehearsal, no runbooks, no central log shipping; the Logs tab still reads a local file.
- Two API replicas: scheduling and token refresh are safe by database locks (tested); IMAP per-mailbox ordering is per process.
