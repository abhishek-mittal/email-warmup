## DB connection

```typescript
// src/db/index.ts
import { drizzle } from 'drizzle-orm/node-postgres';
import { Pool } from 'pg';
import * as schema from './schema';

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 20,
  idleTimeoutMillis: 30_000,
  connectionTimeoutMillis: 5_000,
});

export const db = drizzle(pool, { schema });
export type DB = typeof db;
```

## Query patterns

### Always use prepared statements for hot paths
```typescript
// Good — prepared statement reused across calls
const getActiveInboxes = db.select().from(inboxes)
  .where(eq(inboxes.status, 'active'))
  .prepare('get_active_inboxes');

// Use it
const rows = await getActiveInboxes.execute();
```

### Transactions for multi-table writes
```typescript
await db.transaction(async (tx) => {
  await tx.insert(warmupSends).values(sendRecord);
  await tx.update(poolMembers)
    .set({ reputation: sql`${poolMembers.reputation} + 1` })
    .where(eq(poolMembers.id, receiverPoolMemberId));
});
```

### Pagination pattern
```typescript
const page = await db.select().from(warmupSends)
  .where(eq(warmupSends.senderInboxId, inboxId))
  .orderBy(desc(warmupSends.createdAt))
  .limit(pageSize)
  .offset(page * pageSize);
```

## Migrations

```bash
# Generate migration after schema change
npx drizzle-kit generate --out=src/db/migrations --schema=src/db/schema

# Apply to DB
npx drizzle-kit migrate
```

Rules:
- Always generate a new migration — never edit existing migration files
- Migration file names are auto-timestamped — do not rename them
- Run migrations in CI before starting the app (`db:migrate` npm script)

---

## What you never do

- **Never write raw SQL strings** — use Drizzle's query builder for all queries
- **Never store plaintext tokens or passwords** — all `*Token`, `*Pass` fields must be encrypted before insert (see skill-inbox-connection for encrypt/decrypt helpers)
- **Never edit an existing migration file** — always generate a new one
- **Never purge warmup_sends body inline** — the purge job runs on a schedule (PurgeModule); don't add body-delete logic inside processors
- **Never access the DB directly from a controller** — go through the service layer
